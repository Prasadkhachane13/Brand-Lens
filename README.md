# BrandLens — Enterprise Pre-Publication Brand Governance Platform

BrandLens is a brand-governance web application designed for high-velocity marketing and product teams. It inspects collateral before publishing against brand guidelines, approved facts, terminology, visual identity, accessibility, and confidentiality rules.

---

## Core Principles & Constitutional Rules

1. **Explain, Never Reject**: 100% of findings include severity, exact highlighted text span, a plain-language "why", a citation to an explicit guideline or Approved Source ID, and a proposed fix.
2. **Human Authority**: All corrections are proposals. The human author or editor can **Accept**, **Edit**, or **Reject**. BrandLens **never auto-applies anything**.
3. **Evidence-Linked**: Citations link directly to verified Brand Guidelines or Approved Fact Sources (with active dates and `review_after` expiration verification).
4. **Server-Authoritative RBAC**: Separation of powers enforced in application handlers. **Creators are strictly prohibited from self-approving their own submissions.**
5. **Zero Data Egress Guarantee**: Pure deterministic detection engine runs 100% locally and offline without external API keys. Optional Gemini multimodal intelligence is toggle-gated (default OFF).

Overview

BrandLens is an enterprise-oriented brand governance web application designed for high-velocity marketing and product teams.

Organizations publish content across multiple channels, including websites, social media, email campaigns, advertisements, blogs, product announcements, and press releases. Maintaining consistent brand messaging while ensuring that every piece of content follows approved guidelines can be challenging.

BrandLens addresses this challenge through a centralized pre-publication inspection and approval system.

It evaluates content against brand guidelines, approved facts, terminology standards, visual identity rules, accessibility requirements, and confidentiality policies.

Rather than simply rejecting non-compliant content, BrandLens identifies specific issues, explains why they matter, provides supporting evidence, and proposes appropriate corrections.

The final decision always remains with the human author or reviewer.

The primary objective is simple: ensure that every piece of content is accurate, consistent, compliant, and ready for publication before it reaches the audience.

Core Principles & Constitutional Rules

BrandLens is built around five fundamental governance principles.

1. Explain, Never Reject

Every detected compliance finding is designed to provide:

Severity level indicating the importance of the issue.

Exact highlighted text span identifying the problem.

Plain-language explanation of why the content violates a guideline.

Citation to the relevant Brand Guideline or Approved Source ID.

Proposed correction to help resolve the issue.

Instead of providing unexplained rejection messages, BrandLens makes compliance decisions transparent and actionable.

2. Human Authority

All corrections generated by BrandLens are suggestions, not automatic modifications.

Users can choose to:

Accept: Apply the proposed correction.

Edit: Modify the proposed correction before applying it.

Reject: Reject the finding and provide a reason.

BrandLens never automatically applies suggested corrections without human approval.

3. Evidence-Linked Governance

Compliance findings are connected to explicit brand guidelines and approved factual sources.

The evidence system considers:

Source identification and verification.

Active and expiration dates.

review_after validation.

Source reliability and relevance.

Outdated certifications and unsupported claims.

This ensures that content decisions can be traced back to the information used to justify them.

4. Server-Authoritative Role-Based Access Control

BrandLens implements Role-Based Access Control (RBAC) to enforce separation of responsibilities.

Creators cannot approve their own submissions.

Permissions are enforced through application handlers rather than relying exclusively on frontend button visibility.

This prevents unauthorized approval actions and supports a structured review process.

5. Zero Data Egress by Default

The deterministic detection engine operates locally without requiring external API keys.

Core compliance inspection does not depend on external AI services.

External Gemini multimodal intelligence is optional.

External processing is disabled by default.

AI processing can be enabled through an explicit configuration setting.

This architecture prioritizes privacy, predictable execution, and controlled data processing.

Detection Engine Architecture

The BrandLens detection engine is organized into seven categories of deterministic inspection logic.

Its core inspection functions operate locally and evaluate content against configured brand rules and approved evidence.

1. Tone Detection

Evaluates whether content follows the organization's communication style.

Examples:

Formality scoring.

Maximum sentence length thresholds, such as sentences exceeding 25 words.

Consecutive exclamation marks (!!!).

Banned colloquial expressions such as super dope and mind-blowing.

2. Terminology Detection

Ensures that approved brand terminology is used consistently.

Examples:

Incorrect / Restricted

Suggested Terminology

NW Home

Northwind Home

Eco Mode

EcoMode

cheap

cost-effective

The engine identifies restricted expressions and suggests approved alternatives.

3. Messaging Detection

Checks whether required brand messaging is present and consistent.

Examples:

Required core value proposition:
Intelligent climate control made simple for modern homes.

Call-to-action enforcement.

Detection of unsubstantiated marketing buzzwords.

Verification of approved messaging patterns.

4. Claims Detection

Identifies potentially unsupported marketing claims and numerical statements.

Examples:

Superlative claims such as #1, best-in-class, and guaranteed.

Numerical claims such as saves 45%.

Customer statistics such as 85,000 customers.

Claims that cannot be verified against an ApprovedSource.

Expired certifications and outdated factual references.

For example, the demonstration environment includes a Thermal Modulation Award source that expired on 2024-01-01.

The engine flags the outdated source rather than treating it as valid supporting evidence.

5. Visual Identity Detection

Checks visual assets against registered brand standards.

Capabilities include:

Perceptual Difference Hash (dHash) matching.

Approved logo and asset comparison.

Brand palette hex color validation.

Logo clearspace and distortion rules.

Example brand palette:

Color

Hex Code

Dark Navy

#0B111E

Primary Blue

#2563EB

Teal

#0D9488

6. Accessibility Detection

Identifies common accessibility problems in content.

Examples:

Missing image alternative text: ![]().

Vague alternative text: ![photo]().

Incorrect heading hierarchy, such as H1 followed directly by H3.

Ambiguous links such as [click here].

The objective is to make published content more accessible and understandable.

7. Confidentiality Detection

Identifies potentially sensitive information before publication.

Examples:

Exposed credentials such as sk_live_... and AKIA....

Employee or customer personally identifiable information (PII).

SSN-like patterns: \d{3}-\d{2}-\d{4}.

Internal distribution markers such as [CONFIDENTIAL - INTERNAL ONLY].

Unreleased project codenames such as Project Boreas.

The engine flags these patterns to help prevent accidental disclosure of sensitive information.

Installation & Setup

Follow these steps to run BrandLens locally.

Prerequisites

Make sure you have installed:

Node.js (20.19+ recommended).

npm (Node Package Manager).

Git.

Step 1: Clone the Repository

git clone https://github.com/Prasadkhachane13/Brand-Lens.git

Step 2: Navigate to the Project

cd Brand-Lens

Step 3: Install Dependencies

npm install

Step 4: Configure Environment Variables

The repository includes an .env.example file.

Create your local .env file using the example:

# Windows Command Prompt
copy .env.example .env

Configure the required values:

GEMINI_API_KEY="YOUR_GEMINI_API_KEY"
APP_URL="http://localhost:3000"

Important:

Gemini integration is optional for the deterministic inspection engine.

External AI processing is disabled by default.

Never commit your actual API keys or secret credentials to GitHub.

Configure the Gemini key only if you intend to enable optional AI functionality.

Step 5: Initialize the Database (Optional)

BrandLens includes a Prisma schema configured for SQLite.

Initialize the database migration:

npx prisma migrate dev --name init

Generate the Prisma client:

npx prisma generate

Step 6: Seed Demonstration Data

Run the seed script to initialize the Northwind Home demonstration brand kit and sample collateral.

npm run seed

Step 7: Run the Application

Start the local development server:

npm run dev

Open your browser and navigate to:

http://localhost:3000

Database Architecture

BrandLens includes a Prisma schema configured for SQLite.

The repository also contains data.json, which is used by the Express application for operational data persistence.

The Prisma schema and seed script provide a separate database initialization and seeding workflow. Initializing SQLite does not, by itself, switch the existing Express runtime storage from data.json to Prisma.

Testing

BrandLens includes unit tests for the deterministic detection engine.

Run the test suite:

npm test

The tests use the Node.js built-in test runner through tsx.

TypeScript validation:

npm run lint

These checks help identify implementation errors and maintain the reliability of the inspection engine.

Core Design Principles

BrandLens is designed around five important engineering principles.

1. Explainability

Compliance findings should provide clear explanations, supporting evidence, and actionable recommendations.

2. Human-in-the-Loop Governance

Automated inspection assists human decision-making rather than replacing it.

3. Evidence-Based Validation

Brand compliance decisions should be traceable to explicit guidelines and approved information sources.

4. Separation of Responsibilities

Creators, reviewers, and administrators operate with different permissions and approval responsibilities.

5. Privacy-Aware Processing

Deterministic inspections can run locally without external AI services. Optional external processing is explicitly controlled through application configuration.
